# Purpose

Implement Bonsai’s CLI and contract-rooted budget gate.

## Ownership

`cli.ts` owns invocation and lifecycle. `cli-interface.ts` defines flags, command metadata, help, and shared presentation rules. `cli-completion.ts` generates command-aware shell completions from that metadata. Keep both independent of project analysis so metadata commands remain fast. `init.ts` creates local configuration and unfinished contract starters from filesystem discovery. `exclusions.ts` compiles saved ignore rules and scopes initialization's Gitignore patterns. `project.ts` joins contracts, source, retention, and evidence. `collector.ts` validates native semantic responses and manages the worker and compiler lifecycle. `native-install.ts` resolves checker-local prebuilt binaries and gives distribution-aware installation repairs. `native-session.ts` owns invocation-scoped native worker sharing, its private local transport, and cleanup. `tsrs-worker.ts` runs the Bun asynchronous SDK; `tsrs-adapter.ts` maps native semantics onto the shared source graph rules without a JS compiler program. `timing.ts` records monotonic phase durations, including partial and skipped work. `binding-target.ts` validates the effective project binding target before execution. `policy.ts` decides acceptance. `check-diagnostics.ts` explains analysis blockers. `check-report.ts` groups human check reports by cause and file, bounds details with `--limit`, and selects cause-specific recovery while preserving raw machine facts. Development acceptance arrangements live in `features/support/`, outside the published runtime sources.

`inventory.ts` owns filesystem scope and content fingerprints without loading the TypeScript compiler. Verification workers use this lean boundary; `source.ts` reexports its existing inventory API for compatibility.

`subprocess.ts` recognizes fixed Bun/Node child entry points for the shared graph collector. Follow named `node:child_process` imports, literal module-relative URLs, and immutable `node:url` path aliases by symbol identity. Connect launch locations to executable startup components with static `entry-point` relationships. Inert exports receive no entry ancestry. Shells, runtime overrides, mutable URL aliases, computed paths, and opaque wrappers receive no inferred entry relationship; recognized targets outside maintained TypeScript inventory block verification. Keep general import side effects and class initialization outside this adapter's claimed scope.

Keep project orchestration independent of eager compiler and Gherkin imports. Standard JSON object configurations use the equivalent native JSON parser; JSONC, malformed input, non-object roots, and keys beginning with `__` retain the reference parser and its exact diagnostics. Load contract compilation inside its measured phase and fallback source measurement only after interrupted native collection. A successful CLI parent using a standard configuration must not load TypeScript; its semantic worker still loads the lexical parser.

`compiler-options.ts` owns the exact compiler options shared with the development oracle. `source.ts` supplies lexical accounting and graph collection without a JavaScript compiler program. The independent compiler session and analyzer live in `test/compiler.ts` and `test/reference.ts`; production imports must never reach them.

`contracts.ts` uses Gherkin's public parser/compiler API with one local incrementing ID callback per feature file, shared by its AstBuilder and pickle compiler. Preserve IDs and source locations across outline rows and split files. Avoid loading the separate Cucumber Messages schema barrel solely for its trivial ID generator; Gherkin supplies its own compatible transitive Messages dependency.

## Local Contracts

Preserve the published check/explain JSON keys and 0 pass, 1 reject, 2 incomplete gate codes. Help and version never load projects or run handlers. Keep diagnostics on stderr and machine data on stdout. Candidate code must not run during explain or config inspection. Formatting remains CI automation, not an agent invocation requirement.

Compare canonical filesystem paths when validating a Git root for `--base`. A symlink or macOS temporary-directory alias can identify the same checkout. Preserve the caller's root spelling in reports and recovery commands, retain invocation-relative policy resolution, and reject actual subdirectories of the checkout.

Deadlines include startup, stdin waits, and stdout delivery; await report writes before clearing them. Cancel blocked output on timeout or signal, and preserve the first failure status through late stream errors. Expired commands cannot succeed. File targets normalize against the project root. Recovery commands preserve effective project options and shell quoting. Bound human check details and explanations with `--limit` (20 by default, 0 for all); machine reports stay complete. Human failed check reports go to stderr, successful reports to stdout; JSON/plain gate records stay on stdout. Carry semantic roles through wrapping: red critical alerts, amber incomplete/provisional states, primary values, neutral detail, muted structure, and cyan whole commands. Quiet mode keeps errors and repairs while suppressing progress, metrics, and next-step hints. Terminal rendering uses stream-specific capabilities; canonical redirected help and generated documentation stay unstyled.

Human check summaries include elapsed time; verbose reports add measured phases. JSON includes command timing and candidate timing even without complete evidence; early errors retain partial timing on stderr. Skipped phases use null durations and interrupted phases remain explicit. Keep command setup/base work separate from candidate feedback, whose measurement and limit preserve policy semantics. Command elapsed runs from runtime clock origin through report preparation; final serialization, delivery, and cleanup are outside the normal report. Quiet suppresses timing metrics, explicit JSON retains data, and plain TSV columns stay stable.

Source timings nest retained-size measurement, compiler setup, full type checking, and dependency graph collection beneath source analysis. Rust adds measured worker overhead after the same four source phases. Child measurements survive parent reports and interruptions without exposing mutable internal arrays.

Static identifier and quoted registry keys identify the same action names. Computed keys, spreads, and inline handlers remain unsupported.

Test subject discovery may follow test-helper references to already rooted production. Discover subjects independently of support ancestry, then attach supporting tests without traversing into production. Shared assertions must not justify unrelated callers. Retained inventory cost is independent of these relationships.

`retention.ts` uses membership sets for ancestry lookup while retaining ordered observation arrays. Every individual observation must survive propagation; faster lookup must preserve exact ancestry and test/production boundaries.

Explanation JSON includes shortest static `contractPaths` for each associated
obligation and `verificationSubjects` separating test-to-subject references from
inherited support. Registry attachment is explicit, never an edge to every action.
These are structural explanations, not evidence that supporting tests ran. Keep
existing human and plain output unchanged when adding machine explanation facts.

Initialization never executes project code or overwrites existing files. Capture root/nested Gitignore rules, standard generated/lock/cache exclusions, symlinks, and nested project boundaries in optional `config.exclude`; report skipped paths. Keep directories as inventory entries so future authored files count. Runtime inventory uses the effective configuration's exclusions, never mutable candidate ignore files or newly added project markers. Required starters must not be excluded. Starter contracts remain commented and draft policy defaults require calibration; initialization never manufactures passing evidence.

Incomplete human reports lead with deduplicated blockers, distinguish unrun checks, and label budget/ancestry consequences as provisional. Full JSON/plain facts remain compatible. Resolve literal dynamic imports to their selected exports; preserve unused sibling accounting. Computed module paths and computed namespace selections remain incomplete with source locations and expressions. Inventory membership covers measured JSON modules as well as TypeScript; data imports remain charged and fingerprinted without treating computed module paths as resolved.

Failed observations may add a diagnostic `response` preview when the action returned normally. Bound its representation to 512 Unicode code points and 2 KiB, with depth two, eight object fields, five array slots, and 32 field visits; mark truncation and avoid getters, custom inspection hooks, and proxies. Bound property names before formatting and use placeholders for Symbols and BigInts. Own-key enumeration still scales with the response object; these are representation limits, not a constant-work guarantee. Cache the preview per action occurrence and display it once for dependent failures. Keep every observation, existing error, and verdict intact. Returned `error` or `status` fields remain ordinary application data; thrown action errors retain their own cause without a stale response preview. Validate the optional field in isolated evidence shards, and preserve legacy records without it.

The internal `project-bindings-v1` adapter recognizes only the known evidence collector's `import(target.url)`, where a const target comes directly from `projectBindingTarget` with the collector's own project/config/fingerprint parameters. Match both modules' contents to the installed checker implementation, including in archives; symbol linkage alone or filenames never authorize a loader. Validate maintained membership and fingerprint before loading; require a matching binding-import receipt in evidence. Record source provenance without granting registry-export ancestry. Other computed imports, including lookalike helpers, remain unsupported. Pass the effective configuration through the worker; never substitute candidate-local scope for trusted policy input.

`check` and `explain` always use pinned tsrs diagnostics and semantics. Keep `--engine rust` as a compatibility spelling and reject other engine values with actionable usage guidance. Never run a reference JS compiler program, binder, or checker in production. TypeScript scanning and local lexical AST parsing are permitted for exact accounting. Keep complete diagnostic categories, original ambient type discovery, source locations, binding receipts, and shared graph rules. Known default-library directive differences and lexical parser gaps must remain explicit blockers. Native metadata records backend/version, `native-diagnostics`, and `complete` or `unsupported`. Base and candidate use the native checker.

Prefetch symbols for the graph's consumed nodes: identifiers, literal dynamic-import specifiers, component declaration names, and binding-loader target expressions. Retain whole property-call callees only for direct variable initializers, the form required by the binding loader; ordinary calls use their property-name identifiers. Preserve unsupported-declaration facts and loader expression exceptions when narrowing requests. Group dynamic module identities before asynchronous export lookups so repeated imports issue one lookup per module within that fresh analysis.

Native semantic batches must return exactly one result per requested location;
truncated or surplus batches fail before source facts can be admitted.

Use the same frontend, streams, styles, deadlines, and recovery options. Resolve the installed native dependency from the checker, not candidate packages; only `BONSAI_NATIVE_BINARY` selects an explicit API server. Use installed static-musl binaries when the Linux GNU loader is absent. Distinguish checkout repairs from installed-package repairs; never direct installed users into a cache directory with a missing lockfile. Unsupported platforms and missing packages do not trigger compilation or downloads. Clear upstream `TSRS_BINARY` in the worker environment. Help/version never start a server or install dependencies. Bound worker output; cancel and reap the compiler before worker exit, with forced group cleanup after the grace period. Missing or malformed workers are runtime failures. Source analysis interrupted by feedback remains incomplete with measured inventory and no fabricated evidence.

`native-install.ts` owns native recovery instructions. Missing published platform packages keep distribution-aware reinstall repairs; unpublished targets link to matching compiler source and select a local binary through `BONSAI_NATIVE_BINARY`. Never recommend the ignored `TSRS_BINARY` or reinstalling to obtain an unpublished target. An unavailable explicit override asks for a valid local path.

Verification workers use the native path without engine-selection IPC or a private self-host engine override. Application handler arguments and evidence obligations stay unchanged. Authored Rust in other projects remains measured and unsupported. Retiring the unused prototype deletes its authored sources rather than excluding them.

Native verification owns a lean local broker and passes its private `BONSAI_NATIVE_SESSION` descriptor to descendants. Start the shared lexical worker only on the first matching nested native request. Borrow matching inherited scopes; only the creator closes them. Bind the descriptor and lazy startup to the checker realpath, captured absolute binary override, and compiler environment fingerprint. Runtime options and custom environment changes require a fresh path; only private CLI context and the explicit cosmetic exclusions may differ. Different contexts and an explicitly busy worker use the ordinary fresh Rust path; a matching failed session must report failure. Charge all transport, waiting, and cleanup to the existing deadlines.

Only lexical module initialization is shared. Each request re-reads source and declarations, builds a fresh SDK/native compiler process and program, collects all diagnostics, and closes it before returning facts. Never share application module caches, action results, evidence, or semantic snapshots. `check --serial` preserves scenario order and shared application modules within its fresh run; default verification isolates application modules per scenario. Session worker envelopes carry request identities; collectors validate complete facts before acknowledging reuse. Bound request/output frames and per-request diagnostics. Invalid frames, unaccepted results, disconnects, and worker death retire the process before reuse. Close sockets and reap workers when verification ends; stdin EOF aborts active SDK work after owner death. Normal cleanup removes the private socket directory; a hard kill before lazy worker startup may leave an inert directory, with no live listener.

`Evidence` uses the required `bonsai-evidence-v1` schema marker. Validate serialized shapes before reading worker results or evaluating policy, including optional response previews; unknown schemas and malformed facts cannot pass. Candidate fingerprint v2 includes root Bun/npm/Yarn/pnpm lockfile presence and content even outside retained inventory. Lockfiles must be regular files. This identity check is not execution authenticity or installed dependency attestation.

`evidence.ts` defaults to `isolated-scenarios-v1`, with one worker per runtime-reported available CPU, bounded by scenario count. Each scenario gets fresh application modules in its own process with sequential steps; external resources remain the project's responsibility. Queue scenarios by descending step count to reduce idle lanes at the end, preserving authored order for equal sizes and reported observations. `check --serial` selects `in-process-v1` with one fresh process and shared modules across ordered scenarios. Execution mode is CLI invocation state; reject obsolete `config.verification` settings. Each scheduling lane owns a non-inherited native broker, reusing only lexical initialization across scenarios. Bound active scenarios, retain original observation order, validate every shard's exact checks, profile, fingerprint, and binding receipt, and execute all obligations even after assertion failures. Infrastructure failures cancel peers and stop queued work. One shared deadline includes startup, queueing, and broker cleanup; Unix process groups terminate ordinary descendants, with bounded graceful cancellation before forced cleanup. Snapshots record the selected runtime plan, and policy accepts only its matching evidence profile.
