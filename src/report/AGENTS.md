# Purpose

Render the standalone Bonsai check dashboard from the evaluated invocation.

## Ownership

`model.ts` projects collected facts and effective configuration. `client.ts` owns browser interaction. `template.html`, `styles.css`, and `assets/` preserve the reviewed Bonsai identity. `render.ts` embeds local assets and escaped data. `output.ts` validates destinations and writes atomically. CLI orchestration remains in `../cli.ts`.

## Local Contracts

- Consume the existing decision, snapshot, timing, and effective configuration without rerunning analysis or handlers. Preserve raw verdicts, exact observation ancestry, evidence absence, supporting verification, structural facts, and policy provenance.
- Count every maintained file once at full cost. Specification reach and supporting tests never grant discounts or allowance.
- Keep the reviewed order: file cost versus specification reach, nested retained inventory, then components without links. Show mixed files explicitly and distinguish declaration cost from resource and module-startup components.
- Ratios use recorded component tokens in the selected role, never whole-file cost or runtime coverage. Keep unknown measurements distinct from zero.
- Preserve exact source points, individual numbered callouts, and keyboard/table alternatives. Keep one file workspace with local filters and an explicit return path.
- Normalize maintained-entry membership against collected files without reinspection. Evidence context matching is distinct from completeness and acceptance; preserve raw records and unknown classifications.
- Keep all assets offline, licensed, measured, and packaged. Serialize the referenced TypeScript client function rather than adding unsupported authored JavaScript or a runtime build.
- Escape candidate-controlled strings in HTML and embedded JSON. The private data script is `bonsai-report-data`; it does not replace the public check JSON.
- Validate final and temporary output destinations against effective inventory and canonical filesystem paths. Never narrow policy to make room for output. Write after candidate integrity, under the command deadline and outside candidate feedback; interrupted writes preserve the previous complete report.

## Work Guidance

Use the approved white canvas, OpenRunde typography, lavender palette, and tree mark. Keep code syntax highlighting local. Review semantics and interactions independently.

## Verification

Use the report's focused technical tests and executable report examples, then the repository checks. Browser appearance is a separate check; do not describe DOM stand-ins as visual verification.
