How to read this report Definitions, sources, and what the charts do not claim


Specification link
For non-test source components, a static connection from a specified action through its bound handler and dependencies. Test components can inherit links from already linked source; the configured action registry is associated with required observations explicitly. Bonsai calls these connections contract ancestry. They are not runtime coverage, importance, or proof that every behavior was tested.


A file can be partly linked
Some components in a file may have specification links while others have none. “Contains code with no spec link” refers to those components; it does not mean the entire file is unsupported.


Component roles are path rules
Bonsai's collector marks components in the configured binding file as binding; paths matching test/, tests/, .test. or .spec. as test; other collected components as production. That last name does not establish deployment or runtime use. It can include types and developer tools. Optional file-role facts remain distinct from component roles and deployment knowledge.


Bindings and observation results
A binding maps a public action to its handler. A missing handler makes the check incomplete. When verification runs, its observations fail with an unbound-action error; without valid evidence, their outcomes remain unavailable. A failed response assertion is a different failure. If verification returns no valid evidence, results are unavailable; absence is not a failed assertion.


File tokens and component tokens
The budget charges each complete maintained file once. Component costs omit some imports, comments and scaffolding; they cannot partition the entire file into covered and uncovered percentages. Shared components still pay their full cost.


What is measured, and where?
File costs, component roles, static relationships, ancestry and observation results come from check facts. Specifications are grouped by their .feature paths. Effective settings come from configuration collection; entry counts are derived from those settings and the indexed files. No matched-exclusion list or per-file analysis flag is invented.




Read the accounting, not just the charts Definitions & limitations
A single, finite ceiling
Surface counts unique action–observation pairs. Deduplication never removes required checks. More examples of the same pair do not earn extra allowance.
Reach is context, never a discount
Files retain their complete measured cost. Tests cannot root unsupported production. A reachable wrapper receives no discount. “Shared” and “exclusive” describe static ancestry; neither establishes importance or removable code.
Read the measured snapshot
This offline report contains the evaluated invocation and effective configuration. Specification groups follow their indexed paths. Component classifications describe collector roles, not deployment environments. Source relationships are static, and recorded observations do not substitute for the gate’s evidence validation.
