A few good questions

Small by design.
Explicit about the limits.

Read the roadmap
Does every helper need its own acceptance test?+

No. A helper can inherit contract ancestry through the production component that needs it. Lower-level tests then inherit from retained subjects. A unit test cannot justify otherwise unsupported production code.

Can an agent buy more room with more tests?+

Extra examples, duplicate scenarios, and split files earn no additional allowance. Each required check still has to pass. Only distinct external action–observation pairs affect the surface count.

Is this just a line-count limit?+

Bonsai measures retained source tokens within an explicit maintained inventory, including contracts, bindings, tests, fixtures, and configuration. Formatting outside TypeScript literals creates no headroom. The metric creates consistent pressure; it does not claim to measure comprehension or predict effort.

Does Bonsai delete code automatically?+

Bonsai reports the constraint and blocks acceptance. Your existing coding agent proposes and verifies the change. Unsupported code must be removed, connected to required behavior, or recovered through a legitimate contract correction.

What can I use today?+

The working alpha supports TypeScript and named in-process handlers, a small executable Gherkin grammar, static symbol ancestry, retained-size budgets, and candidate-bound contract results. Use it for a supported pilot and review the maintained inventory.

HTTP and queue adapters, coverage and mutation evidence, and hardened merge enforcement are on the roadmap. Contract handlers execute with your privileges; use an external sandbox for untrusted candidates. Read the full limits ↗
