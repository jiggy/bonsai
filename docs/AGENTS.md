# Purpose

Explain Bonsai’s supported behavior and limits.

## Ownership

Design baseline, BDD workflow (`bdd.md`), roadmap, command reference, CLI review evidence (`check-ux-review.md`), native collector evaluation (`native-prototype.md`), performance profiling and native checker research (`performance.md`), and the distinction between executable behavior contracts and full self-budget acceptance.

README's optional structural-policy section owns `control-depth-v1` counting and limit semantics. Keep configured enforcement distinct from additive source diagnostics and retained-token accounting; no default depth limit is implied.

`verification.md` owns concrete supporting-runner configuration, exercised format/runtime versions, quality-floor semantics, snapshot/evidence identities, and their authentication limits.

## Local Contracts

Document actual commands, defaults, streams, and exit codes. Keep unsupported adapters and admission guarantees explicit. Distinguish the internal validated binding-loader boundary from general computed imports, and development oracle comparisons from native full-root admission checks under the saved deadline.

The roadmap treats Bonsai's own allowance overrun as non-blocking development
information until the first mature release. Preserve and report the real gate
verdict without relaxing policy. Trusted-admission plans must distinguish
candidate CI validation from independently controlled checker distribution,
policy, sandbox execution, and required-status publication.

Keep the BDD guide authoritative for discovering stakeholder rules, reviewing implementation-independent examples, and deciding which product observations qualify for the global allowance. Distinguish BDD from red/green implementation discipline: Gherkin, public JSON, real CLI execution, and fault sensitivity alone do not qualify a feature. Describe the literal action–selector counter and human eligibility review accurately; do not claim automatic semantic counting. Preserve technical regression assertions when moving them out of features, and report allowance changes separately from code savings. Neither structural ancestry nor selected fault checks prove complete behavioral coverage.

Document fixed subprocess entry-point syntax separately from runtime coverage. Child launches root executable startup, not entire modules or exports. Keep unsupported launch forms and general import side effects explicit; distinguish definition-time class effects from dormant bodies. Test-helper subject discovery uses established production ancestry; supporting helper ancestry cannot justify unrelated callers.

Document literal text resource reads as a bounded production/binding adapter:
whole-file data references never root executable exports, and retained file cost
stays independent. Keep exact supported URL, filesystem API, encoding, and text
format limits explicit. Test fixture ownership and universal dependency
completeness remain separate gaps.

Keep command elapsed time, candidate phase durations, and policy feedback measurements distinct. Document timing endpoints and partial/interrupted measurements; profiling doesn't change acceptance or deadline limits.

Document concurrent isolated verification as the default, with runtime CPU-sized workers bounded by scenario count, fresh application processes, sequential steps, and one overall deadline. `check --serial` preserves shared application modules across ordered scenarios. Execution mode is an invocation choice, not project configuration. Process separation does not isolate external resources. Compare profiles on identical inventories and obligations; label historical configuration/fingerprint differences separately from current runtime metadata and changed outcomes.

Keep native semantic conformance, lexical accounting, and runtime evidence distinct. Label benchmark process reuse, timing endpoints, workloads, and engine responsibilities; never present structural-only timing as an equivalent full-gate speedup. Rust is the sole production engine, and authored Rust stays measured with explicit unsupported analysis until an adapter exists.

Document native analysis as the default and `--engine rust` as a compatibility spelling. `--engine typescript` is unsupported. Keep development compiler oracles outside published runtime sources. Reference comparisons run in development tests, never inside a native check. Preserve explicit TypeScript-version gaps, Bun asynchronous transport requirements, native platform support, and the distinction between analysis speed, completed verification, and gate acceptance. Never compare an incomplete run with a completed gate as an equivalent speedup.

Document prebuilt platform coverage and source-checkout versus installed-package repairs. Never imply a prepared npm version has been published or ask users to compile a missing published platform package. Unpublished targets may use an explicit local build matching the pinned SDK through `BONSAI_NATIVE_BINARY`; distinguish this from prebuilt package support and automatic installation.
